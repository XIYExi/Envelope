# Envelope V3 项目梳理路线图

## 项目现状总结

这是一个**全栈低代码项目生成平台**，从 V2（UmiJS 拖拽玩具）重写为 V3（Next.js + Electron 桌面应用）。纯 AI 操刀开发，存在两套代码并存的技术债。

**已完成的功能**：F01-F04（Monorepo脚手架、平台App Shell、Supabase集成、项目CRUD）、F06（Schema引擎）、F09（物料系统）

**未完成**：F05（Electron）、F07（画布编辑器）、F08（属性编辑器）、F10-F23（数据模型、路由、流程引擎、代码生成等）

## Schema 引擎解析（已完成阅读）

### 整体结构
`packages/engine/src/` 分三层：
- `schemas/` — 5 个 Zod Schema 定义项目的数据结构
- `validation/` — 校验函数 + 版本迁移机制
- `canvas/` — 画布状态管理（Zustand store）

### 5 个核心 Schema

1. **project.schema.ts** — 项目元数据（名称、描述、主题配置、SEO、Supabase 引用）
2. **page.schema.ts** — 页面结构（组件树，递归的 ComponentNode，支持 12 列网格布局）
3. **routes.schema.ts** — 路由配置（树形结构，支持动态路径、认证守卫、中间件）
4. **db-schema.schema.ts** — 数据库定义（表、列类型、外键、索引、RLS 策略）
5. **auth.schema.ts** — 认证配置（OAuth 提供商、重定向 URL、会话设置）

### 关键设计模式
- **递归 Schema**：ComponentNode 和 RouteNode 使用 `z.lazy()` 实现树形嵌套
- **类型推导**：所有 TypeScript 类型从 Zod Schema 推导（`z.infer`），保证类型和校验一致
- **版本迁移**：`migration.ts` 实现了链式迁移机制，虽然目前没有注册任何迁移

### 数据流
```
用户操作 → Zustand Store (canvas/editor) → Schema 校验 → API 存储到 Supabase
                                                    ↓
                                            代码生成器读取 Schema → 输出 Next.js 源码
```

## Supabase 集成解析（已完成阅读）

### 架构分层
```
middleware.ts (认证守卫)
    ↓
app/api/ (Next.js Route Handlers)
    ↓
lib/services/project.service.ts (业务逻辑)
    ↓
lib/supabase/server.ts + client.ts (Supabase SDK)
    ↓
supabase/migrations/001_platform_tables.sql (数据库)
```

### 7 张数据库表（全部带 RLS）
| 表名 | 作用 | 关键字段 |
|------|------|----------|
| projects | 项目主表 | user_id, name, config JSONB |
| project_pages | 页面定义 | project_id, path, schema JSONB |
| project_routes | 路由配置 | project_id, page_id, auth_required |
| project_flows | 业务逻辑 | project_id, yaml_content, trigger_event |
| project_models | 数据模型 | project_id, table_name, schema JSONB |
| project_endpoints | API 端点 | project_id, method, path, flow_id |
| project_auth | 认证配置 | project_id, providers JSONB |

### 认证流程
1. `middleware.ts` — 非公开路径检查 session，无 session 重定向到 /login
2. `/api/auth/callback` — OAuth 回调，交换 code 为 session
3. 所有表启用 RLS，用户只能访问自己的项目（通过 user_id 关联）

### API 路由
| 方法 | 路径 | 作用 |
|------|------|------|
| GET | /api/projects | 获取项目列表 |
| POST | /api/projects | 创建项目（Zod 校验） |
| GET | /api/projects/[id] | 获取单个项目 |
| PATCH | /api/projects/[id] | 更新项目 |
| DELETE | /api/projects/[id] | 删除项目 |
| POST | /api/projects/[id] | 复制项目（含 pages/routes） |

### 技术债
- `duplicateProject` 只复制了 pages 和 routes，没有复制 flows、models、endpoints、auth
- `project.service.ts` 没有事务保护，复制操作可能部分失败
- 没有分页、搜索、过滤功能
